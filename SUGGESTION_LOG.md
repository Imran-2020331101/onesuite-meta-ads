# Suggestion Log — OneSuite Meta Ads Landing Page

Forward-looking improvements from the full-project audit ([AUDIT_REPORT.md](AUDIT_REPORT.md)). These are things that work today but could be better — as distinct from [ISSUE_LOG.md](ISSUE_LOG.md), which tracks things that are actually broken or non-compliant.

Priority is relative to this page's one job: converting and measuring paid Meta traffic.

| # | Category | Suggestion | Rationale | Effort | Priority |
|---|---|---|---|---|---|
| 1 | Performance | Migrate all `<img>` tags to Astro's `astro:assets` `<Image>`/`<Picture>` components | Automatic resizing, format negotiation (WebP/AVIF), and `srcset` generation — the root cause behind [ISSUE_LOG.md](ISSUE_LOG.md) #4 is easiest to fix permanently by changing the pipeline, not just re-exporting the current 5 files by hand. | Medium | High |
| 2 | Performance | Self-host Inter (via `@fontsource/inter` or Astro's `astro/fonts`) instead of Google Fonts CDN | Removes an external DNS/TLS round trip, improves LCP slightly, and avoids sending visitor IPs to Google at font-request time — relevant if EU ad traffic is in scope. Pair with trimming the requested weight list down to what's actually used once #13 in the issue log is fixed. | Low | Medium |
| 3 | Performance | Preload the hero LCP image | Once `profitibility.png` is resized (issue #4), add `<link rel="preload" as="image" href="...">` in `LandingLayout.astro`'s `<head>` for that specific image to shave time off the Largest Contentful Paint metric. | Low | Medium |
| 4 | Attribution | Preserve ad click-ids/UTM params through to the app signup flow | Every CTA links straight to `https://app.onesuite.io` with no query string. Once a Pixel is installed (issue #2), consider forwarding `fbclid`/`utm_*` params from the landing page URL onto the outbound CTA links so attribution survives into the app's own signup analytics. | Medium | High |
| 5 | Compliance | Add a cookie/consent notice before shipping the Meta Pixel | Installing Meta Pixel (issue #2) introduces third-party cookies; if any EU/UK traffic is targeted, a consent mechanism (even a lightweight banner) will likely be required alongside it. Bundle this with the pixel work rather than as an afterthought. | Low–Medium | High (once #2 ships) |
| 6 | Accessibility & simplification | Rebuild the FAQ accordion on native `<details>/<summary>` | Gets `aria-expanded`-equivalent state, keyboard support, and open/close behavior for free from the browser, removing the need for the custom `click` listener in `FacebookAdsFAQ.astro` entirely while also resolving issue #11. | Low | Medium |
| 7 | Maintainability | Introduce a shared `CTAButton.astro` component | There are 12+ hand-styled "Start Your Free Trial"/"Claim offer" buttons across sections, each with its own near-duplicate CSS block. A single component (accepting `href`/`label`/`variant` props) would make future brand or copy changes a one-file edit instead of a nine-file hunt. | Medium | Medium |
| 8 | Maintainability | Extract shared "section header" markup (eyebrow + `<h2>` + subtitle) into a small reusable component/pattern | Nearly every section repeats the same `eyebrow` / heading / subtitle DOM+CSS structure with a different class prefix. Consolidating reduces the ~9 parallel copies of very similar CSS and makes the design tokens in `global.css` easier to actually wire up (ties to issue #19). | Medium | Low–Medium |
| 9 | SEO / ops | Run Lighthouse / PageSpeed Insights (and Meta's own Landing Page Experience checks) once this is live | This audit was static-only (no live URL to test against). Ad "Quality Ranking" on Meta is influenced by landing page load performance, so a live Core Web Vitals check should happen once the image/font fixes above ship, and periodically after. | Low (ongoing) | Medium |
| 10 | Security / hosting | Add baseline security headers at the hosting layer | No CSP, `X-Frame-Options`, or `Referrer-Policy` are configured anywhere (no `public/_headers`, `netlify.toml`, or `vercel.json` present). Static marketing pages are low-risk, but this is a cheap, standard hardening step once a hosting target is chosen. | Low | Low |
| 11 | Documentation | ~~Note the relationship between this repo and the main `onesuite.io` site in `README.md`/`AGENTS.md`~~ | **Done** — `README.md` was rewritten (see [ISSUE_LOG.md](ISSUE_LOG.md) #22) and now explains where the real page lives and why `noindex` is intentional, so this is no longer only inferable from a code comment in `meta-sales-page.astro`. | Low | Done |
| 12 | Tooling | Use `npm ci` (lockfile-exact installs) in any deploy pipeline, and commit the current `package-lock.json` change intentionally | `package-lock.json` currently shows as modified in git with no corresponding `package.json` change — worth reviewing what shifted and committing deliberately rather than leaving it dangling, and locking future installs to the committed lockfile in CI/deploy. | Low | Low |
| 13 | Content / conversion | Consider real customer avatar photos (with permission) in `TestimonialsGrid.astro` | Currently all testimonials use colored initials as avatars. Real photos (once consent for #3 in the issue log is confirmed) typically read as more credible social proof than initials, especially for a cold-traffic landing page. | Low | Low |
| 14 | Robustness | Add a project-specific 404 page | None currently exists; Astro falls back to a generic dev-only message. Low-traffic path for a single-page funnel, but cheap to add for polish. | Low | Low |
